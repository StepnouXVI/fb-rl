\section{Вторая идея: Графовое планирование (Search on the Buffer)}

\subsection{Построение топологического графа достижимости}

После неудачи с наивным делением пополам стало очевидно: среда представляет собой сложный топологический лабиринт с жесткими стенами, и кратчайший путь должен искаться глобально с гарантией проходимости. В литературе по офлайн-RL для этого используется парадигма Search on the Buffer~\cite{eysenbach2019search, park2025ogbench}.

Я реализовал построение ориентированного графа $G = (V, E)$ поверх оффлайн-датасета:
\begin{enumerate}
    \item \textbf{Ориентиры (Landmarks)}: Сэмплируется $N$ репрезентативных состояний $\{s_1, \dots, s_N\}$ из оффлайн-буфера ($N=1000$ для Medium, $N=2000$ для Large).
    \item \textbf{Матрица достижимости}: Для всех пар ориентиров вычисляется направленная мера $R_{ij} = F(s_i, B(s_j))^\top B(s_j)$.
    \item \textbf{Квази-метрическая стоимость ребра}:
    \addequation{
        c(s_i, s_j) = -\log \left( \frac{\max(R_{ij}, 10^{-6})}{\max_{k} R_{kk}} \right).
    }{eq:graph_cost}
    \item \textbf{Двухуровневая фильтрация ложных переходов}: Чтобы исключить «просачивание сквозь стены», ребра фильтруются:
    \begin{itemize}
        \item По евклидову радиусу: $c(s_i, s_j) = \infty$, если $\|s_i[:2] - s_j[:2]\| > R_{\text{edge}}$ ($R_{\text{edge}} = 3.5\,\text{м}$).
        \item По порогу FB-достижимости: $c(s_i, s_j) = \infty$, если $R_{ij} < \tau_{\text{cutoff}}$ ($\tau_{\text{cutoff}} = 35.0$).
    \end{itemize}
\end{enumerate}

По полученной разреженной матрице стоимости один раз при старте задачи запускается алгоритм Дейкстры, возвращающий оптимальный дискретный маршрут $\mathcal{P} = [s_{\text{start}}, v_1, v_2, \dots, v_K, g]$.

\subsection{Механизм скользящего окна упреждения (Sliding Lookahead)}

Первые запуски показали важную физическую особенность: если просто переключать целевой вейпоинт дискретно (по достижению радиуса $1.0\,\text{м}$), 8-суставный муравей резко тормозит, теряет кинематический импульс и вписывается в углы по ломаной траектории.

    \label{fig:search_on_buffer}

Чтобы сделать движение робота плавным и устойчивым, я ввел \textbf{механизм скользящего упреждения (Sliding Lookahead)}: на каждом шаге $t$ по положению агента $s_t[:2]$ отслеживается локальная проекция на путь, и целевой токен выбирается на фиксированном расстоянии упреждения $L_{\text{lookahead}} = 2.6\,\text{м}$ вперед вдоль геодезической линии графа.

\subsection{Результаты учителя}
Такой планировщик (названный \texttt{Dijkstra Teacher}) показал резкий прирост надежности: успешность в лабиринте Medium выросла до **78.0\%**, полностью решив проблему застревания в длинных коридорах. Однако этот подход сохраняет два недостатка:
\begin{enumerate}
    \item Необходимость хранения матрицы графа и вычислительная сложность $O(N^2)$ при построении.
    \item Опора на стандартный \texttt{high\_actor}, который все еще не обучен специфике локальной динамики обхода углов.
\end{enumerate}
